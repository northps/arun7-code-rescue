เกม 3D ฝึกเขียนโปรแกรม Arduino C/C++ ตั้งแต่ศูนย์ ใช้คู่กับบทเรียนใน `02_programming` (P00–P08) และ `01_robot` ผู้เล่นต้องเขียนโค้ดจริงเพื่อสั่งอุปกรณ์บนยานอวกาศ แล้วดูโค้ดทำงานทีละบรรทัดในฉาก 3D

เล่นได้บนมือถือ Android (แนวตั้ง) แท็บเล็ต และโน้ตบุ๊ก

## วิธีรัน

ต้องมี Node.js 18 ขึ้นไป

```bash
cd C:\programming_course\07_game

npm run dev
```

เปิดลิงก์ที่ขึ้นในหน้าต่างคำสั่ง (ปกติคือ `http://localhost:5190`) เล่นบนมือถือที่ต่อ Wi-Fi วงเดียวกันได้ โดยเปิดลิงก์บรรทัด **Network** (`http://192.168.x.x:5190`)

| คำสั่ง | ทำอะไร |
| --- | --- |
| `npm run dev` | เปิดเกมแบบพัฒนา แก้ไฟล์แล้วหน้าเว็บเปลี่ยนตามทันที |
| `npm run build` | ตรวจชนิดข้อมูล แล้วสร้างไฟล์ static ลง `dist/` (เอาไปวางบนเว็บเซิร์ฟเวอร์ใดก็ได้ หรือห่อเป็น APK) |

## วิธีเล่น

1. หน้าแรก กด **เริ่มเล่น** ทุกด่านเปิดด้วยบัตรบทเรียน 1 หน้า (เปิดดูซ้ำได้จากปุ่ม 📖)
2. หน้าจอแบ่งเป็น ฉาก 3D (บน หรือซ้ายบนจอกว้าง) กับโค้ด (ล่าง หรือขวา)
3. แก้โค้ดตามชนิดของโจทย์ แล้วกด **▶ รัน**

| ชนิดโจทย์ | วิธีเล่น |
| --- | --- |
| เติมช่องว่าง | แตะช่อง `?` ในโค้ด แล้วแตะชิ้นคำสั่งด้านล่าง |
| เรียงบรรทัด | แตะบรรทัดที่มีแถบสีฟ้า แล้วกด ▲ ▼ |
| หาที่ผิด | กดรันเพื่อดู error ก่อน แตะบรรทัดที่คิดว่าผิด แล้วเลือกบรรทัดที่ถูก |
| พิมพ์โค้ดเอง | พิมพ์ในช่องโค้ด บนมือถือมีแถบปุ่ม `;` `{ }` `==` เหนือคีย์บอร์ด · บนคอมกด Ctrl+Enter เพื่อรัน |

**โหมดพิมพ์เอง:** ปุ่ม `⌨ พิมพ์เอง` ที่แถบบนของหน้าเล่น เปิดแล้วโจทย์ทุกชนิดจะกลายเป็นช่องพิมพ์โค้ด (ช่องว่างแสดงเป็น `___` ให้พิมพ์แทน) ปิดแล้วกลับเป็นแบบแตะเลือก ค่านี้จำไว้ในเครื่อง

ระหว่างรัน: บรรทัดที่กำลังทำถูกไฮไลต์ มุมขวาบนของฉากแสดงค่าตัวแปร มุมซ้ายล่างแสดง Serial Monitor

- **โค้ดคอมไพล์ไม่ผ่าน:** บิตส่ายหัว เกมแสดงข้อความ error ภาษาอังกฤษแบบเดียวกับ Arduino IDE พร้อมคำอธิบายไทยและบรรทัดที่ผิด
- **โค้ดรันได้แต่ผิด:** เกิดผลในฉาก (บิตชนผนัง สัญญาณเตือน เคลธบุกเข้ามา) แล้วบอกว่าอะไรยังไม่ถึงเป้า บั๊กที่เครื่องจริงไม่เตือน เช่น `if (x = 5)`, `int` ล้น, หารจำนวนเต็ม จะขึ้นเป็น "ข้อสังเกต"
- **หลายกรณี:** บางข้อรันซ้ำกับค่าเซนเซอร์หลายชุด ใส่คำตอบตายตัวจึงไม่ผ่าน
- **ดาว:** ★★★ ผ่านครั้งแรกไม่ใช้คำใบ้ · ★★ พลาดไม่เกิน 2 ครั้งหรือใช้คำใบ้ 1 ครั้ง · ★ ผ่านได้ในที่สุด
- ความคืบหน้าเก็บในเครื่องที่เล่น (`localStorage`) ล้างได้จากปุ่ม 🗑 ในแผนที่ด่าน

## วิธีเพิ่มด่าน

ด่านเป็นข้อมูลล้วน ไม่ต้องแตะโค้ดของเกม

1. คัดลอกไฟล์ด่านที่ใกล้เคียง เช่น `src/game/levels/act1/l03.ts` ไปเป็นไฟล์ใหม่ แก้ `id` (ต้องไม่ซ้ำ) ชื่อ เนื้อเรื่อง และบัตรบทเรียน
2. วาดห้องใน `world.map` แถวบนสุดคือทิศเหนือ

   | ตัวอักษร | ความหมาย |
   | --- | --- |
   | `#` | ผนัง |
   | `.` | พื้น |
   | `B` | บิต (ต้องมี 1 ตัว ทิศเริ่มต้นกำหนดที่ `dir`) |
   | `D` | ประตู |
   | `P` | แผ่นเหยียบเปิดประตู |
   | `T` | แผงควบคุม (แสดงค่าที่ส่งให้คำสั่งใน `actions` หรือข้อความ Serial) |
   | `L` | โคมไฟ |
   | `A` | ที่ยืนของเคลธหลังประตู |
   | `X` | ลัง |
   | `G` | ยานกู้ชีพ |

3. เปิดคำสั่งที่ด่านใช้ได้
   - `api`: `forward` `backward` `turnLeft` `turnRight` `openDoor` `closeDoor` `lockDoor`
   - `pins`: อุปกรณ์บนขาของบอร์ด เช่น `{ 13: 'lamp', 7: 'lock' }` ใช้กับ `pinMode` / `digitalWrite`
   - `actions`: คำสั่งส่งค่า เช่น `enterCode: { args: 1, label: 'แป้นรหัส', opensDoor: true }`
   - `sensors`: คำสั่งอ่านค่า เช่น `{ scanAliens: 0 }` · `inputs`: ค่าที่ `readNumber()` จะได้
4. เขียนโจทย์ใน `puzzles` เลือก `kind` เป็น `blank` `order` `fix` หรือ `type` (รูปแบบของแต่ละชนิดอธิบายใน `src/game/types.ts`)
5. กำหนดเป้าหมายใน `goal` เช่น `door: 'open'`, `at: 'pad'`, `serial: "SOS"`, `pins: { 13: 1 }`, `set: { enterCode: [1750] }` และถ้าต้องการทดสอบหลายค่า ใส่ `cases`
6. ลงทะเบียนใน `src/game/levels/index.ts` (import แล้วเพิ่มในรายการ `LEVELS` ตามลำดับที่จะให้เล่น) ถ้าเป็นองก์ที่เคยเป็นด่านล็อก ให้ลบชื่อออกจาก `planned` ขององก์นั้น
7. รัน `npm test` ชุดทดสอบจะตรวจให้เองว่า คำตอบของโจทย์ใหม่ผ่านจริง โค้ดตั้งต้นยังไม่ผ่าน และข้อมูลถูกรูปแบบ

ถ้าด่านใหม่ต้องการอุปกรณ์แบบใหม่ (เช่น ป้อมปืนขององก์ 2) ต้องเพิ่ม 2 ที่: ตรรกะใน `src/game/world.ts` (เมธอด `call`) และภาพใน `src/view/worldView.ts` (เมธอด `load` กับ `apply`)

## ภาพและโมเดล

- ฉาก 3D สร้างด้วยโค้ดทั้งหมด จึงเล่นได้โดยไม่ต้องดาวน์โหลดอะไร
- หน้าแรกใช้ฉาก 3D จริงของเกมเป็นพื้นหลัง ถ้าวางภาพ (กว้างอย่างน้อย 600 px) ไว้ที่ `public/art/title.jpg` เกมจะใช้ภาพนั้นแทน เหมาะกับภาพ render แนวตั้งจาก AI
- ถ้ามีโมเดล 3D ไฟล์ `.glb` (เช่น ที่สร้างจากบริการ AI) วางไว้ใน `public/models/` ด้วยชื่อ `bit.glb` (หุ่นบิต หันหน้าไปทาง +Z), `kleth.glb` (เคลธ) หรือ `pod.glb` (ยานกู้ชีพ) เกมจะใช้แทนโมเดลที่สร้างด้วยโค้ด และปรับขนาดให้สูงประมาณ 1 ช่อง **ส่วนนี้ยังไม่ได้ทดสอบกับไฟล์จริง**

## ทำเป็นแอป Android (ยังไม่ได้ทำ)

เกมออกเป็นไฟล์ static และใช้ path แบบสัมพัทธ์ จึงห่อด้วย Capacitor ได้ ต้องมี Android SDK และ JDK 17

```bash
npm install @capacitor/core @capacitor/cli @capacitor/android
```

```bash
npx cap init "โค้ดกู้ยาน อรุณ-7" com.arun7.coderescue --web-dir dist
```

```bash
npm run build
```

```bash
npx cap add android
```

```bash
npx cap sync android
```

จากนั้นล็อกแนวตั้งโดยเพิ่ม `android:screenOrientation="portrait"` ที่ `<activity>` ใน `android/app/src/main/AndroidManifest.xml` แล้วสร้าง APK

```bash
cd android
```

```bash
gradlew.bat assembleDebug
```

ได้ไฟล์ที่ `android/app/build/outputs/apk/debug/app-debug.apk` ทุกครั้งที่แก้เกม ให้รัน `npm run build` แล้ว `npx cap sync android` ก่อนสร้าง APK ใหม่

ข้อควรรู้: ฟอนต์ Sarabun และ IBM Plex Mono โหลดจาก Google Fonts ถ้าเครื่องไม่ต่ออินเทอร์เน็ต เกมจะใช้ฟอนต์ของเครื่องแทน (ยังเล่นได้ปกติ) ถ้าต้องการให้เหมือนกันทุกเครื่อง ให้ดาวน์โหลดฟอนต์มาไว้ใน `public/` แล้วแก้ `index.html`

## ข้อจำกัดของตัวแปลภาษา

รองรับสิ่งที่ใช้ในคู่มือไวยากรณ์ทั้ง 16 หัวข้อ (รายการเต็มใน `docs/game-design.md` หัวข้อ 4.3) ที่ **ไม่** รองรับ: pointer, `struct`, `class`, อาร์เรย์หลายมิติ, `#include` ไลบรารี (ถูกข้าม), ตัวดำเนินการระดับบิต (`<<` `>>` `&` `|` `^`) ข้อความ error เลียนแบบคอมไพเลอร์จริงในกรณีที่พบบ่อย แต่ไม่ได้เหมือนทุกตัวอักษรในทุกกรณี
